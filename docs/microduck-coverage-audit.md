## 当前规则与设计缺陷

1. **采集范围是固定信源。** worker 定时抓 RSS/Atom 等已配置入口，不会自动搜索整个互联网或顺着周报链接发现并订阅项目。原来的 18 个启用源没有 Pollen / Microduck 的官方入口；Hugging Face 仅接了 LeRobot releases，无法覆盖另一仓库的机器人。加入实体/关键词标签本身也不会扩大采集范围。
2. **每篇材料只评一个单位。** 预筛先判断机器人关联，再按七种内容类型、实质份量/信息增量/证据强度/共振面/可用性五轴打两次分。周报没有先拆成各项目的独立事件，因此一个传闻或主标题会影响整篇解释。这是模板的单篇处理方式在汇总材料上的不足。
3. **精选按来源级别设门槛。** T1=60、T1_5=65、T2=76，低于 50 用较简单的摘要写法。官方源门槛较低是为了优先一手材料，媒体门槛较高是为了压制转载和宣传噪声；这些数字从原 AI 模板继承，没有完成机器人领域的人工样本校准。双次评分也不是独立事实核验。
4. **历史材料与新进展分开。** 首次只回灌最近 8 条，保留原始发布时间并标记历史材料。后续更新走常规采集；不会把旧公告改成今天的新闻。

当时选择 RSS 和官方仓库是为了用已有采集器完成可维护的首版，验证解析、日期和正文。验证成功只说明这几个入口能用，并不说明机器人行业覆盖充分。缺少小型机器人项目的一手源，以及没有拆解周报，确实造成了这次遗漏；它不是一条排除 Microduck 的关键词规则。

## 此次修复

- 增加 [Microduck 官方博客 RSS](https://pollen-robotics.com/microduck/blog/rss.xml)。实际解析到 [Meet Microduck](https://pollen-robotics.com/microduck/blog/introducing-microduck/)，原日期为 2026-08-27，生产正文提取器得到 6,682 字符。它会保留历史日期，不作为当天新发布事件。
- 增加 [Microduck GitHub releases](https://github.com/pollen-robotics/microduck/releases.atom)，当前解析到 10 条。用既有 `ingestNoiseFilter.dropMarkersTitleOnly` 排除标题中的 `-dev.` 开发构建，稳定版本正常进入原筛选流程。正式版本发布仅证明发布动作，不能自动证明实机效果。
- 两个来源均设为 T1 / first_party，公开短摘要与原文链接，全文权限继续关闭。配置在 `industry/sources.json`，原采集器检查结果追加到 `docs/source-validation.json`，旧记录保留各自的检查时间。
- 通过幂等导入只增加新来源，不覆盖管理员对既有来源的配置。不改门槛、历史文章评分或日期，不强制入选。

此次补齐 Microduck 的直接入口。通用“周报拆成多事件”仍未实现；其他仅在汇总文章里出现、没有直接信源的项目仍可能漏评。阈值及摘要质量仍需要人工样本校准，不能用这次补源代替召回率或事实准确率验证。
